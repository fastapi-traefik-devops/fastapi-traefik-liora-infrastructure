# Phase 1 Jenkins security decisions

- The only privileged component is the isolated Docker-in-Docker daemon needed to build nested containers. Its TLS endpoint is private to the CI build network. The host Docker socket and Kubernetes credentials are never mounted. Since privileged DinD shares the host kernel, use this setup only for trusted repository code on a dedicated CI host. Public fork PR execution needs a disposable isolated worker before it is enabled.
- The registry publisher is a separate permanent Docker agent. It cannot access DinD or its certificates and receives `ghcr-write` only through Jenkins Credentials Binding inside its publication stage. It accepts image archives as data and checks Jenkins build success, the Git revision, gate report, and archive hashes before authentication.
- High and Critical findings block image and frontend dependency scanning. `pip-audit` blocks every reported dependency advisory. Gitleaks checks full Git history and the current repository tree. Scanner failures are never converted to success.
- Gitleaks' narrow SealedSecret exception matches only Bitnami encrypted ciphertext in exact existing paths. A plaintext `stringData` or a changed path remains a finding. The Jenkins plugin-lock exception matches only public plugin coordinates in one exact lock file; plugin versions are separately verified against the update center.
- The three historical `.gitleaksignore` fingerprints refer to one old Jupyter demo session token repeated three times in upstream documentation from 2018. The demo token is not used by current code. Treat any still-live session derived from it as compromised and revoke it at its original service; history was not rewritten. No active project credential was found in the scan.
- Pin updates to base images, tools and plugins must be reviewed and scanned. Lock files and exact digests are in this directory; `ci/validate_phase1.py` verifies their syntax and rejects a Kubernetes plugin. Do not add blanket vulnerability exceptions. Any unresolved advisory needs a concrete owner, impact and replacement plan before accepting a build.
- The latest upstream release binaries of Gitleaks, crane and Trivy contained vulnerable Go libraries. Their exact official source archives are checksum-verified and rebuilt in disposable stages with Go 1.27.2 and compatible fixed dependencies. The application backend remains Python; no compiler or source tree is copied into runtime images. The source hashes and explicit dependency patches are in `tools.lock.json`.
- Docker 29.9.0 replaces the older daemon image. Its remaining vulnerable runtime components are rebuilt from pinned upstream sources, with seccomp retained in runc. Unused daemon CLI plugins and ctr are removed. Git LFS is removed from the agent because this repository has no LFS configuration.
- Bootstrap runs `ci/audit_ci_images.py` before switching containers. Controller, agent and daemon scans run sequentially to avoid cache locks. High/Critical findings or scanner errors stop migration; no vulnerability allowlist was introduced for these fixes.
